# IPOCraft: Master Product Evolution (Version 2)
**Document Status:** Final Strategy Blueprint
**Objective:** Transforming IPOCraft into the premier, industry-leading IPO research platform.

---

## 1. Executive Summary
This document serves as the single source of truth for the evolution of IPOCraft. Moving beyond fundamental bug fixes and code structure, this roadmap defines the strategic trajectory required to elevate IPOCraft from a functional IPO data viewer into an authoritative, daily-habit research platform. We prioritize privacy-first personalization, institutional-grade analytics for retail investors, and programmatic SEO capture, all wrapped in a flawlessly consistent, accessible UI.

## 2. Product Vision
**Vision:** To be the most trusted, neutral, and data-dense IPO research platform in India, empowering retail investors with institutional-grade insights without resorting to manipulative "stock tips" or requiring invasive user accounts.
**Core Principles:** Neutrality, Factual Accuracy, Privacy-First Personalization, High Information Density with Low Cognitive Load.

## 3. Current Strengths
*   **Aesthetic Foundation:** The dual-font strategy (Outfit/Inter) and glassmorphic touches give the platform a modern, premium feel compared to legacy competitors (like Chittorgarh).
*   **Tech Stack:** Next.js App Router and Supabase provide a robust, edge-ready foundation capable of extreme scaling.
*   **Neutrality:** The commitment to factual data over sensationalist advice builds long-term trust.
*   **Mobile-Aware Navigation:** The fixed bottom mobile nav is an excellent pattern for thumb-reachability on a data-heavy site.

## 4. Current Weaknesses
*   **Component Monoliths:** Pages like `app/ipo/[slug]/page.tsx` are monolithic, hurting maintainability.
*   **Accessibility Failures:** Over-reliance on micro-typography (`text-[10px]`) alienates users and fails WCAG guidelines.
*   **Mobile Table UX:** Horizontal scrolling tables on mobile create friction.
*   **Over-fetching:** Backend queries lack strict column definitions, wasting bandwidth.
*   **Lack of Stickiness:** Beyond checking a single GMP, there are few localized, privacy-safe hooks (like watchlists) to bring users back daily.

## 6. UI Improvements
*   **Pixel-Perfect Consistency:** Standardize `border-radius`. Cards should globally use `rounded-xl` (12px), inner badges `rounded-md` (6px). 
*   **Contrast Enhancement:** Upgrade all secondary text from slate-400 (`#94a3b8`) to slate-500 (`#64748b`) against white backgrounds.
*   **Tabular Lining:** Apply `font-variant-numeric: tabular-nums;` to all GMP and subscription data so numbers align perfectly vertically in lists.
*   **Interactive Affordances:** Ensure every clickable card has a subtle hover lift (`-translate-y-[2px]`) and a shadow bump (`shadow-md`).

## 7. UX Improvements
*   **Progressive Disclosure:** IPO detail pages are overwhelming. Hide complex institutional data behind "View Full Details" accordions, prioritizing Retail/HNI data on initial load.
*   **Skeletons over Spinners:** Replace all generic loading spinners with layout-accurate skeleton loaders to reduce perceived load time.
*   **Empty State Illustrations:** Replace "No IPOs found" text with branded, helpful empty states that guide users to educational content.

## 8. Mobile Improvements
*   **Table-to-Card Toggle:** Automatically transform all tables (GMP, Financials) into vertically stacked cards on viewports `< 768px`. Do not rely on horizontal scrolling.
*   **Touch Targets:** Ensure all interactive elements (tabs, buttons, links) have a minimum touch area of `44x44px`.
*   **Sticky Summary Header:** On mobile, when scrolling deep into an IPO detail page, keep a microscopic sticky header at the top showing the IPO Name and Current GMP so context is never lost.

## 9. Information Architecture Improvements
*   **Site-Level:** Introduce a "Learn" or "Academy" hub in the main navigation. Group all educational guides (What is GMP, How Allotment Works) into a structured curriculum rather than disparate blog posts.
*   **Page-Level (IPO Detail):** 
    1. Key Takeaways (New)
    2. Vital Stats (Price, Dates, GMP)
    3. Subscription Status
    4. Financial Health
    5. Anchor Investors
    6. Related IPOs (New)

## 10. Backend & Data Improvements
*   **API Design:** Transition from RPC calls fetching everything to strictly typed, column-specific queries.
*   **Caching:** Implement `revalidateTag` triggered by Supabase Webhooks for instantaneous cache invalidation when GMP/Status changes, eliminating stale data.
*   **Search:** Integrate full-text search capabilities in Supabase to handle fuzzy matching (e.g., searching "Tata" should find "Tata Technologies").

## 11. New Feature Recommendations
*   **Key Takeaways Module:** A bulleted, AI-generated (but editorially approved) summary at the very top of every IPO page detailing pros, cons, and risks. 
*   **"What's Changed" Indicators:** Small visual deltas (e.g., "GMP up ₹10 since yesterday") to give instant temporal context.
*   **Historical GMP & Subscription Trends:** Visual sparkline charts showing how GMP and subscriptions evolved over the 3-day bidding window.
*   **Cross-Linking Engine:** Automatically link "Registrar: Link Intime" to a page showing all past IPOs handled by Link Intime and their listing performance.

## 12. Rejected Ideas
*   *Registrar-wise / Lead Manager Analytics:* **Rejected.** IPOCraft is for retail investors. Lead Manager analytics is an institutional feature that adds extreme UI complexity with near-zero retail value.
*   *Automated OG Image WhatsApp Sharing:* **Rejected.** High risk of brand degradation and association with unregulated tipsters.
*   *Flashing "FOMO" Triggers:* **Rejected.** Violates the platform's neutral, non-manipulative ethos.

## 13. Design System Roadmap
1.  **Tokens:** Define absolute scales for spacing (4, 8, 12, 16, 24, 32px), typography (12, 14, 16, 20, 24, 32px), and color semantics (Status: Success/Warning/Danger/Info).
2.  **Components:** Build a strict UI library: `BaseCard`, `DataRow`, `StatusBadge`, `MetricWidget`.
3.  **Documentation:** All developers must use the exact Tailwind classes defined in the token system; no arbitrary values (`w-[13px]`).

## 14. Product Roadmap

### 15. MVP Priorities
1.  **Typography & Contrast:** Eradicate 10px text; fix slate-400 contrast.
2.  **Admin Security:** Migrate destructive Supabase calls to Server Actions.
3.  **Mobile Tables:** Refactor `GmpTableClient` to list-view on mobile.
4.  **Local Watchlist:** Deploy `localStorage` favoriting.

### 16. Phase 2 Priorities
1.  **Component Refactoring:** De-monolithize `app/ipo/[slug]/page.tsx`.
2.  **Programmatic SEO:** Launch `/allotment-status` and `/gmp-today` sub-routes.
3.  **Interactive Calculator:** Deploy the Listing Profit Calculator.
4.  **Push Notifications:** Integrate factual "Allotment Out" web pushes.

### 17. Long-Term Vision
1.  **Historical Analysis Database:** The ultimate repository of IPO performance correlating GMP accuracy with actual listing gains over a 5-year horizon.
2.  **Broker API Integrations:** Direct, inline IPO applications via Kite Connect/Upstox APIs.
3.  **Personalized Dashboard:** A strictly local, privacy-first dashboard tracking the user's historical applications and theoretical profits.

## 18. Engineering Complexity
*   **High:** Refactoring the God Component; Supabase Webhook cache invalidation.
*   **Medium:** Programmatic SEO dynamic routing; Broker API integrations.
*   **Low:** Typography scaling; Local Watchlist implementation; Profit Calculator.
